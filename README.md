# VPS Manager

用于 Debian / Ubuntu 服务器的交互式管理脚本，集中完成系统初始化、网络调优、代理部署、端口转发、防火墙、流量配额和 Telegram 通知。

适合管理个人 VPS、代理落地机和中转机。运行后输入菜单编号即可操作，安装和配置由脚本执行。

## 功能与特点

| 功能 | 用来做什么 |
|---|---|
| 一键初始化 | 为新系统安装依赖，配置网络、防火墙、监控和安全更新，减少逐台手工配置 |
| XanMod 与 BBR v3 | 在兼容的独立 VPS 上安装内核，调整 TCP 拥塞控制；实际效果取决于线路和负载 |
| 带宽与网络调优 | 按确认的带宽、内存和中转/落地角色设置缓冲区及队列参数 |
| 代理部署 | 管理 Snell，以及 sing-box 的 SS/SS2022、SOCKS5、Hysteria2 节点 |
| Realm 转发 | 将中转机的入口端口转发到落地机，组合不同服务器的线路 |
| nftables 与 Fail2Ban | 控制开放端口、限制来源 IP，封禁反复尝试登录 SSH 的地址 |
| 流量配额与到期管理 | 按端口统计用量，超额暂停，管理节点有效期 |
| Telegram 通知 | 将登录、配额、DDNS 和程序更新消息分别投递到群话题 |
| TCPing 监控 | 提供一个供哪吒等监控系统探测 TCP 延迟和可达性的端口 |
| 系统安全更新 | 自动安装官方安全补丁，需要重启时默认在上海凌晨 4 点执行检查 |
| Cloudflare DDNS | 公网 IPv4 变化后更新域名的 A 记录 |

脚本使用原生 **nftables**，自动保存自己的规则并配置开机恢复；代理节点创建时会处理相应的本机防火墙规则。程序下载失败时保留原程序，受管理的配置修改会先校验，应用失败时尝试恢复原状态。

## 安装前准备

- 推荐干净的 **Debian 12/13、Ubuntu 22.04/24.04**，使用 root 执行。系统需要 APT、以 systemd 为 PID 1，以及内核 nftables 支持；不支持 CentOS。
- v2 不提供旧 v1/iptables 配置迁移。旧 v1 机器应重装后使用；已有网站、Docker、Kubernetes 或自定义路由防火墙的主机不适合直接执行一键初始化。
- 云平台安全组、供应商端口限制也必须允许访问。本机防火墙放行不能代替这些设置。
- LXC/OpenVZ 等共享内核容器需要相应权限，例如 CAP_NET_ADMIN。脚本自动跳过无法由容器管理的内核、Swap、宿主网络参数等项目；普通 Docker 容器不适用。

**NAT 和容器不是同一个概念。**NAT 表示外部地址或端口经过映射；容器表示与宿主共享内核。独立 VPS 也可能使用 NAT，应以供应商实际配置为准。

### NAT 机器如何填写端口

例如供应商给出的映射是：

| 公网访问入口 | 服务器内监听端口 | 传输协议 |
|---|---|---|
| 192.0.2.10:24073 | 55000 | TCP |

安装代理时填写本机端口 **55000**，客户端填写公网地址和端口 **192.0.2.10:24073**。示例 IP 仅用于说明，请换成供应商提供的地址。

只有供应商明确将外部端口和内部端口设成相同值时，两边才填同一个端口。SSH 映射独立于代理端口，不要将它占用；只有 TCP 映射的端口不能用于 Hysteria2 的 UDP 服务。

## 安装与第一次使用

### 下载运行

在新系统的 SSH 终端中完整复制下面这一条命令。它会在缺少 curl 时先安装依赖，再下载固定正式版并检查脚本语法：

~~~bash
(command -v curl >/dev/null || { apt-get update -qq && apt-get install -y -qq curl ca-certificates; }) && curl -fL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/Bud668/vps-mgr/v2.0.5/vps-mgr.sh -o vps-mgr.sh && bash -n vps-mgr.sh && chmod 700 vps-mgr.sh && ./vps-mgr.sh
~~~

安装后保留脚本的原路径，防火墙和定时任务会引用它。以后回到这个目录执行：

~~~bash
./vps-mgr.sh
~~~

已安装的机器使用 **菜单 16 → 5** 更新脚本；保留原来的文件名和目录，包括原先使用的 vps-mgr-beta.sh。

### 完成初始化

1. 选择 **菜单 1：一键初始化**。脚本会自动识别环境，无需再选择“完整”或“简化”模式。
2. 按提示填写服务器名称、带宽和机器角色；需要通知时填写 TG 配置。
3. 查看末尾的未完成项目。安装了新内核时，最后会询问是否重启以启用内核；防火墙初始化不要求中途重连 SSH。
4. 如已重启，重新登录并运行脚本；随后根据用途选择 **7 Snell、8 Realm 或 9 sing-box**。
5. 用自己的客户端验证连接，再按需设置配额、白名单和 DDNS。

初始化主要设置如下：

| 项目 | 默认行为或填写方法 |
|---|---|
| IPv6 | 默认关闭；需要时在 **6 → 3** 开启。使用 IPv6 SSH 登录时会拒绝直接关闭，须先改用 IPv4 或控制台 |
| DNS | 默认 Cloudflare 1.1.1.1 / 1.0.0.1；可选 Google 8.8.8.8 / 8.8.4.4，回车或 3 秒内未确认使用默认值 |
| 服务器名称 | 用于主界面、节点名称和通知识别，例如 Tokyo_01 |
| 带宽 | 单位为 **Mbps**。测速结果不符合实际时，手工填写供应商给出的端口带宽 |
| 机器角色 | 默认“落地”，侧重较少连接的吞吐；“优化线路/中转”侧重高并发。角色用于参数调优，不会自动创建转发规则 |
| Swap | 磁盘可用空间 ≥3GB 时新建 1GB；2.5～3GB 时建 512MB；更少时跳过。已有启用的 Swap 保持不变 |
| 防火墙 | 默认 DROP，保留 SSH 和必要网络通信；业务端口随节点配置放行，不预开 80/443 |
| Fail2Ban | 默认 24 小时内 SSH 登录失败 3 次后永久封禁来源 IP |
| TCPing | 默认使用 9999；新装时被占用才向后找空闲端口，已有实例保留原端口 |
| 每日检查 | 默认开启 Realm/sing-box 新版本提醒；脚本自动更新默认关闭 |
| 安全补丁 | 默认启用官方安全补丁及上海凌晨 4 点按需重启 |

XanMod 需要受支持的 CPU 和系统环境，容器不会更换宿主内核。容器只读或挂载的 DNS 文件会保留宿主配置。已上线的服务器用对应子菜单维护，避免反复执行整套初始化。

## 代理怎么选与怎么部署

### 当前脚本支持哪些代理

| 类型 | 入口 | 适用场景与要点 |
|---|---|---|
| Snell | **7** | 使用 Surge 等兼容客户端；当前默认安装服务端 v5.0.1，输出 Snell 配置行 |
| SS/SS2022 | **9 → 1** | 需要加密代理且客户端支持相应方法；默认 2022-blake3-aes-256-gcm，也可选 aes-128-gcm |
| SOCKS5 | **9 → 2** | 需要账号密码和来源白名单的代理入口；协议本身不加密，适合可信网络等场景 |
| Hysteria2 | **9 → 3** | 客户端支持 Hy2，且链路和供应商允许 UDP；默认使用自签证书和 salamander 混淆 |

**sing-box 核心支持的协议不等于本脚本已提供部署菜单。**当前没有 REALITY、VLESS、AnyTLS 安装入口。不要将手工配置的其他协议直接混入本脚本管理的 sing-box 配置，后续菜单操作会重新生成配置文件。

Hysteria2 输出的链接包含 insecure=1，表示跳过服务端证书验证；这不是自动申请的受信任证书。对服务端身份验证有要求时，需要自行配置证书或客户端支持的证书校验方式。

### 只用一台落地机

以 SS2022 为例：

1. 完成初始化后进入 **9 → 1 → 2：新增节点**。
2. 选择 SS2022，填写监听端口。公网 VPS 可回车随机分配；NAT 机器必须按映射填写。
3. 将输出的 ss:// 链接导入支持该加密方法的客户端；NAT 机器核对外部地址和端口。
4. 以后从 **9 → 1 → 1** 查看节点，从 **9 → 1 → 3** 删除节点。

Snell 首次进入菜单 7 会引导安装并创建节点；已有 Snell 时，从 **7 → 1** 继续添加节点。客户端使用脚本输出的地址、端口、密钥及协议版本。

同机的 SS、SOCKS5、Hysteria2 共用 sing-box 服务。增加、删除节点或修改 ACL 时会重新应用配置，可能短暂影响其他 sing-box 节点。

### 中转机加落地机

~~~text
客户端 → 中转机的 Realm 入口 → 落地机的代理端口 → 目标网站
~~~

1. 先在落地机安装 Snell 或 SS 等代理，并确认直连可用。
2. 在中转机选择 **8：安装 Realm**；已有 Realm 时用 **8 → 2** 手动填写落地机地址和端口，也可用菜单 10 智能粘贴配置。
3. 为中转入口选择可访问的本机端口。后期修改规则后，选择 **11：重启 Realm** 应用。
4. 客户端保留落地节点的协议与密钥，将连接地址、端口改成中转机的公网入口。

Realm 负责转发，不会替你安装落地代理或更换加密协议。**当前脚本生成的 Realm 默认配置用于 TCP 转发**，不要据此认为 Hysteria2 等 UDP 协议也能直接使用这套中转配置。

菜单 12 只检测目标 TCP 端口是否可连接，不验证代理密码、完整协议握手或流媒体解锁能力；目标临时故障时，先确认原因再删除规则。

### SOCKS5 白名单怎么填

从 **9 → 2 → 2** 新建节点，按提示先填写允许连接它的来源 IP 或 CIDR；以后用 **9 → 2 → 4** 修改白名单。**白名单为空会拒绝所有来源**，即使用户名和密码正确也不能连接。

直接连接时填客户端的公网出口 IP；链式连接时填 SOCKS5 服务器实际看到的上一跳出口 IP。家庭公网 IP 变化后，需要相应更新白名单。该入口默认只开放 TCP。

## 防火墙和防护功能

### 常用防火墙操作

| 入口 | 操作 |
|---|---|
| **5 → 1** | 初始化或恢复本脚本防火墙的开机加载；已有规则会保留 |
| **5 → 2** | 手动开放一个本机 TCP、UDP 或双协议端口 |
| **5 → 3** | 关闭普通放行、按规则编号删除，或清理某端口关联规则 |
| **5 → 4** | 管理 IP 黑白名单 |
| **5 → 5 / 6 / 7** | 分别查看详细规则、实际监听、拦截与内核日志 |
| **5 → 8** | 切换安全 DROP / 开放 ACCEPT 模式；通常保留 DROP |
| **5 → 9** | 重建基础防火墙链；保留业务集合，但会移除基础链的手工编辑 |
| **5 → 10** | 管理 SSH 专用放行端口，不修改 SSH 服务自身的监听配置 |

开放端口只是允许网络访问，不会启动监听程序。关闭普通端口放行也不一定等于封禁：SSH、TCPing、临时测试有各自的规则，开放模式下还有默认放行。

脚本只管理自己的 inet vps_mgr 表。首次初始化发现其他防火墙管理服务或现有规则时会拒绝接管；无需为了本脚本另行启用带全局清空规则的 nftables.service。

### Fail2Ban CN 屏蔽与域名 ACL 有什么区别

| 防护 | 作用 | 使用提示 |
|---|---|---|
| Fail2Ban，菜单 **2** | 根据 SSH 失败登录记录封禁来源地址 | 可以将自己的固定管理 IP 加入白名单；该白名单不绕过代理 ACL 和配额 |
| CN 屏蔽，**9 → 1 → 4** | 按 SS 端口拒绝中国大陆来源 IP 的连接 | 国内客户端直接连接该端口会受影响；不是禁止访问中国网站 |
| 域名 ACL，**9 → 1 → 6** | 对 SS 入站拒绝指定域名及其子域的请求 | 只作用于脚本管理的 SS 入站，不是全系统防泄露功能 |

SS 的 **9 → 1 → 5** 更新 CN 地址库，**9 → 1 → 7/8** 添加或查看 ACL 域名。SOCKS5 的来源白名单与以上几种防护分别管理。

## Telegram 通知怎么配置

准备一个 Bot Token、启用话题的 Telegram 群，以及四个话题。将机器人加入群并允许它发送消息；Bot Token 可通过 Telegram 的 @BotFather 创建机器人获取。

进入 **3 → 1**，或在初始化的 TG 提示中按下面顺序粘贴六行：

| 行数 | 填写内容 | 用途 |
|---|---|---|
| 1 | Bot Token | 发送消息的机器人凭据 |
| 2 | 话题群 Chat ID | 通常是 -100 开头的数字，不是群名称或链接 |
| 3 | SSH 话题 ID | 登录及 Fail2Ban 相关通知 |
| 4 | 配额话题 ID | 流量预警、暂停及配额报告 |
| 5 | DDNS 话题 ID | IP 变化、健康与错误通知 |
| 6 | 程序更新话题 ID | Realm/sing-box 新版本，以及系统安全更新失败、待重启提醒 |

话题 ID 可从该话题“复制链接”的末尾数字获取。群 ID 可从自己机器人 Bot API 的 getUpdates 响应中的 message.chat.id 确认；群 ID 与话题 ID 是两个不同的值。

整段粘贴六项会自动进入验证。内容隐藏，但会显示已接收项数；核对群和话题后输入 y 保存。逐行输入时每行按回车；只填 2～5 项时连按两次回车结束。支持注释和空行，单独输入 q 放弃。

保存后用 **3 → 4** 测试推送。更新话题未配置时，程序更新和安全补丁通知只记本地日志，不会改发 SSH 话题。多台服务器可以共用一组群和话题，通过各自服务器名称区分消息。

节点链接、代理密钥和 Bot Token 仅用于自己的配置；分享排错截图时应遮住这些内容。

## 流量配额与到期管理

进入 **13 → 1**，选择端口并设置月配额、别名和可选到期日期。适合按节点分配用量，或在供应商流量耗尽前暂停业务。

- 流量按端口的**入站与出站字节之和**统计，和供应商账单口径可能不同；纯数字额度按 GB 处理，采用 1024 进位。
- 每 5 分钟巡检，用量达到 75% 提醒，达到限额后通过防火墙暂停端口。此时代理程序仍可能显示“运行中”。
- 自然月按上海时区重置；流量超额暂停可在新月恢复，手工暂停不会自动恢复。
- 到期日期当天仍有效，超过该日后暂停；**到期过去 7 天且仍因到期暂停，会删除对应节点或 Realm 规则**。
- 统计有巡检和落盘间隔，突然断电可能丢失少量未落盘用量，不作为精确计费依据。

常用操作：**13 → 3/4** 暂停或恢复，**13 → 5** 立即发送日报，**13 → 6/7** 安装或停止配额定时器。日报默认在服务器本地时间 21:00 发送。

续期时先修改额度或到期日期，再恢复端口，避免下一次巡检再次暂停。**13 → 2** 删除的是配额管理并撤销暂停，不是删除代理节点；停止巡检也不会自动恢复已经暂停的端口。

| **6 → 6** | 修改服务器名称 |
| **6 → 7** | 安装/修复、查看、改端口或卸载 TCPing 监听 |
| **6 → 8** | 启用/修复或停止官方安全补丁自动安装与按需重启 |

TCPing 是一个供监控平台建立 TCP 连接的监听端口，**不是哪吒 Agent**。初始化完成后，将显示的“公网 IP:端口”填到哪吒等平台的 TCPing 监控目标中即可。

默认端口为 **9999**，实际端口以脚本显示为准。NAT 机器还需要供应商提供公网映射；只有两个业务端口时，不要仅为了监控占用正在使用的代理端口。查看状态及启动日志用 **6 → 7 → 3**，修复用 **6 → 7 → 1**，手动指定端口用 **6 → 7 → 4**。

菜单 4 的测速模式只临时放行 **TCP/UDP 5201**，需要手工运行 iperf3 服务及测试客户端；2 小时后端口放行自动到期，再选菜单 4 可提前关闭。普通 Ping 不需要开启测速模式。

## 程序检查 脚本更新与系统补丁

这几项分别管理：

| 任务 | 默认设置 | 操作入口 |
|---|---|---|
| Realm/sing-box 版本检查 | 每天上海 05:00～06:00 检查并提醒，不自动安装核心 | **16 → 6** 开关每日任务 |
| 管理脚本自动更新 | 默认关闭；开启后只自动安装同大版本正式版 | **16 → 7** |
| 手动更新管理脚本 | 下载、校验并备份替换原脚本；跨大版本需二次确认 | **16 → 5** |
| 手动更新代理核心 | 更新后可能重启对应代理服务并断开连接 | **16 → 1 Snell / 2 sing-box / 3 Realm** |
| 系统安全补丁 | 默认安装官方安全补丁，并配置凌晨 4 点按需重启 | **6 → 8** |

菜单 **16 → 4** 当前只按检查结果更新 Snell 和 Realm；更新 sing-box 和脚本请使用各自入口。Snell 升级前核对[官方发布说明](https://kb.nssurge.com/surge-knowledge-base/release-notes/snell)和客户端兼容性。

关闭 **16 → 6** 会同时停止每日版本提醒和脚本定时更新；系统安全补丁由自己的任务管理，不受这个开关影响。手动跨大版本确认并不提供配置迁移能力。

### 凌晨 4 点自动重启怎样工作

安全补丁仅来自 Debian/Ubuntu 官方安全仓库，不自动更新 XanMod、Snell、Realm、sing-box 等第三方程序，也不做发行版升级。

启用安全更新后，默认在 **上海时间 04:00** 检查系统待重启标记。只有确实需要重启、软件包安装完整且包管理空闲时才执行；忙碌或安装异常时顺延，关机期间错过也不会开机后补执行。服务器本地时区不影响这个时间。

这项功能没有独立选择开关。**6 → 8 → 1** 启用/修复安全更新及按需重启，**6 → 8 → 2** 停止后续自动安装和定时重启；正在运行的安装任务不会被强行中断。

已有机器仅替换脚本不会生成新的定时器，需要执行一次 **6 → 8 → 1** 完成配置。重启会短暂断开连接，软件包安装过程本身也可能重启某些服务。

## Cloudflare DDNS

公网 IPv4 经常变化、希望客户端始终使用同一个域名时，可使用菜单 **18**。固定 IP 机器不需要为了代理部署额外开启它。

1. 将域名交给 Cloudflare 管理，准备目标域名和 API Token。Token 可限定到该域名，授予 Zone Read 与 DNS Edit 权限。
2. 首次进入菜单 18 按向导填写配置。逐项手动配置时先在 Cloudflare 建好对应 A 记录；快速粘贴配置会尝试创建缺失记录。
3. 运行首次检测并启动服务。以后 **18 → 2** 立即检查、**18 → 3** 看日志、**18 → 4** 修改配置。

当前管理**一个 A/IPv4 记录**，使用灰云 DNS only。默认每 10 秒检查，DNS 缓存仍会影响客户端实际看到新地址的时间。它不会申请额外公网端口、提供内网穿透或建立 Cloudflare Tunnel。

**18 → 5** 停止服务，**18 → 6** 清理本机 DDNS 服务和配置；不会删除 Cloudflare 上的 DNS 记录。通知使用 TG 的 DDNS 话题。

## 主界面状态怎么看

| 显示 | 含义 |
|---|---|
| nftables 运行中 · 策略 DROP | 默认拦截未经允许的入站访问，按规则放行业务 |
| 已保存 · 开机恢复已启用 | 本脚本规则已保存并配置开机加载 |
| SSH ● 端口 | 脚本判断该 SSH 登录端口已放行，或当前为开放模式；不等于已验证公网连通性 |
| SSH ○ 端口 | 该端口未被脚本判断为已放行，不表示 SSH 程序停止 |
| 端口(t) / 端口(u) / 端口(t/u) | 分别表示 TCP、UDP、两种协议的放行 |
| [TCPing] / [测试] | 分别是监控端口和临时测速端口 |
| CN 屏蔽 / 域名 ACL | 对应代理防护的启用状态；关闭本身不是故障 |
| BBR v1 / v3 / 不可用 | 当前运行内核的检测结果，安装新内核后尚未重启可能仍显示旧状态 |
| 代理连接 0 (TCP) | 当前统计到的代理 TCP 连接为 0；空闲时正常，也不能据此判断 UDP 节点是否工作 |

## 常见问题与排错

### 节点已经安装 为什么连不上

依次核对：客户端地址和协议 → 本机端口监听（**5 → 6**）→ 本机防火墙 → 云安全组或 NAT 映射 → 来源白名单、CN 屏蔽、配额暂停。随后查看 **菜单 14** 的服务日志。

SS2022 客户端必须支持相应加密方法；SOCKS5 白名单不能留空；Hysteria2 需要 UDP；NAT 客户端使用外部映射端口。

### 装了 XanMod 为什么还不是 BBR v3

先检查是否已经重启并加载新内核，再用 **6 → 4** 检测。可查看：

~~~bash
uname -r
sysctl net.ipv4.tcp_congestion_control
~~~

输出 bbr 只表示使用 BBR，不足以区分 v1/v3。内核安装失败、GRUB 仍选择旧内核或容器共用宿主内核时，需要处理对应原因；重装代理不会改变运行内核。

### Realm 修改后为什么没有生效

后期修改规则需要选择 **菜单 11** 重启 Realm。它会中断当前转发连接，主菜单的待重启提示用于提醒这一步。

### 重启后 TCPing 或防火墙没有运行

先用 **6 → 7 → 3** 看 TCPing 状态和日志。若防火墙开机恢复未就绪，使用 **5 → 1** 修复，再使用 **6 → 7 → 1** 修复 TCPing，无需重跑完整初始化。

如果提示 nftables 无权限或缺少 CAP_NET_ADMIN，需要供应商或宿主调整权限，反复安装软件无法补足这项能力。

### TG 输入不显示 是不是没有粘贴成功

输入隐藏是为了避免凭据留在终端画面。观察接收进度，核对随后显示的群和话题；用 **3 → 4** 测试发送。更新话题是配置第 6 项，缺失时更新通知只记日志。

### 更新脚本后要不要重新初始化

通常不用。脚本替换与生成系统配置是两件事，具体功能需要时使用其“启用/修复”入口。旧机器增加凌晨 4 点按需重启时，执行 **6 → 8 → 1**；不要为此重跑菜单 1。
